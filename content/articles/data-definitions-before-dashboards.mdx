## Executive summary

Two charts can be internally correct while telling different stories because they use different definitions. A useful metric needs a management question, a scope, a calculation, a source, and an owner.

## Context

Terms such as active supplier, open order, and realized spend are not self-explanatory. Their meaning depends on time windows, transaction status, and whether taxes or cancellations are included.

## A metric definition card

Capture the definition alongside the data model so it can be reviewed rather than recreated in each chart.

1. Question: which decision should this metric support?
2. Definition: what is counted, over which period, and with which exclusions?
3. Source: which records support the calculation?
4. Ownership: who maintains the definition and investigates exceptions?

## Practical example

In a fictional dashboard, active supplier could mean one order in 3, 6, or 12 months. Those windows answer different questions. Label the chosen window and test it against the category's normal purchasing cycle before treating a supplier as dormant.

## Check the records as well as the definition

The [Government Data Quality Framework](#reference-uk-data-quality) distinguishes completeness, timeliness, and accuracy. Having all required records does not mean their values match reality. Which checks matter depends on the intended use.

For the fictional active-supplier metric, this note proposes the following checks:

| Check        | Example question                                                           |
| ------------ | -------------------------------------------------------------------------- |
| Completeness | Are orders from every included site present, with a supplier identifier?   |
| Timeliness   | Through which date is the extract current?                                 |
| Accuracy     | Does a sampled order's supplier and date agree with its underlying record? |

Record the extract cutoff and any known missing sites beside the result. These purchasing examples are an interpretation of the framework, not prescribed KPI rules. Even a clean extract still needs an agreed definition of an included order.

## Key takeaways

Review one metric definition before adding another chart. Automation can make a definition repeatable; it cannot establish that the definition is appropriate.

## Related reading

The [W3C Data Quality Vocabulary](#reference-w3c-dqv) distinguishes a metric from a measurement and describes metadata that helps a reader assess fitness for purpose. This Working Group Note offers a useful conceptual connection. Applying that distinction to a purchasing dashboard is an interpretation in this developing note; the source does not prescribe a procurement metric.
